## 0. 守るべき前提（CLAUDE.md と同じ）
- 各ゲームは `games/<slug>/index.html` 1枚（＋`assets/`）で自己完結。`src/shared/` を import しない。共通部品はマーカー展開のみ。
- 絵文字禁止（スプライト `#ic-xxx` か同流儀のインラインSVG）。取り消せない操作（投了・退出・リセット・配り直し）は `asobibaConfirm()`。タップ領域44px・本文12px以上・`dvh`・safe-area変数。
- 書体: `--font-ui`（Zen Kaku Gothic New）／`--font-display`（Shippori Mincho B1）／数字は `--font-num` を各ゲームで上書き可。Google Fonts の `<link>` は各ページ head に個別に。
- デザインは DESIGN-UPGRADE.md の水準（ウェイト階層・余白・世界観1つ）。「全部900」禁止。
- ビルド `npm run build` が通ること。検証は Playwright 375×812。

## 1. 共通部品（新設2つ・`src/shared/`）

### 1-1. `online.js` — オンライン部屋（マーカー `<!-- @shared:online -->` → `<script type="module">` で展開）
Firebase（**プロジェクト umauma-737d6**・うまうまレースと同じ設定値・**匿名認証あり・App Checkは使わない**）。Firestore **`rooms/{docId}`**、`docId = "<slug>-<4桁コード>"`（うまうまの数字コードと衝突しない）。ホスト不要の**トランザクション合意方式**：各クライアントが `runTransaction` で「読む→純粋関数で次の状態→version+1 で書く」。全員 `onSnapshot` で追従。
```js
// window.AsobibaOnline（モジュールscript。ゲーム本体も <script type="module"> にしてマーカーの後に置けば順序が保証される）
await AsobibaOnline.init({ slug:"othello" });          // firebase初期化＋匿名ログイン。失敗時は throw（UIは「オンラインは使えません」）
const me = AsobibaOnline.uid();                         // 匿名uid
const code = await AsobibaOnline.createRoom({ slug, name, maxPlayers, minPlayers, initialState, settings }); // 4桁コード文字列を返す。自分がseat0/host
const room = await AsobibaOnline.joinRoom(code, { slug, name });  // 満席/不在/開始済みは Error(message は日本語)
const unsub = AsobibaOnline.subscribe(code, (room) => { ... });  // room は下記 Room 型。unsub() で解除
await AsobibaOnline.update(code, (room) => { /* 純粋に書き換えた新roomを返す。変更なしなら null */ }); // runTransaction。競合時は自動再試行
await AsobibaOnline.addCpu(code, { name });             // host限定。players に {uid:"cpu-<rand>", cpu:true}
await AsobibaOnline.start(code, (room) => initialState); // host限定。status→"playing"、state を作る
await AsobibaOnline.leave(code);                         // 自分を抜く（playing中は cpu:true に差し替えて残す＝ゲームが止まらない）
AsobibaOnline.heartbeat(code);                           // 20秒ごと lastSeen 更新（subscribe中は自動）。60秒無反応の人は「離脱中」表示用に isAway(player) が true
AsobibaOnline.isHost(room);                              // 自分がホストか（hostUid が離脱60秒超なら、生存している最小seatが自動でhostを引き継ぐ＝update内で判定）
AsobibaOnline.shareUrl(code);                            // 招待URL（location の hash に code）
```
```ts
type Room = {
  slug: string; code: string; hostUid: string;
  status: "lobby"|"playing"|"ended";
  players: { uid:string; name:string; seat:number; cpu:boolean; lastSeen:number; }[];
  settings: object;          // ゲーム固有（ルール選択）
  state: object|null;        // ゲーム固有。純粋関数で遷移
  version: number; createdAt: number; updatedAt: number; seed: number;
}
```
- **CPU席はホストが動かす**: ホストの subscribe コールバックで「手番がcpu席」なら `cpuMove()` を計算し 600〜1200ms 後に `update()`。ホスト交代時も同じ。
- **隠し情報（手札・山札）は state に入る＝devtoolsで見れば見える**。家族・友人用の割り切り（uma-race/back10と同じ構造）。UI上は `publicView(state, mySeat)` で自分以外の手札を伏せて描く。
- 権限エラー（permission-denied）が出たら「オンライン対戦の準備ができていません（管理者へ）」と出し、ローカルモードは使える設計。ルールを足す必要が出た場合のために `docs/firestore.rules`（案）を同梱する。
- 招待: `#<code>` 付きURL。ホーム画面に「部屋を作る／コードで参加」。名前は localStorage `asobiba.name` で共有（既存ゲームと同じキーがあればそれに合わせる）。

### 1-2. `cards.js` — トランプ描画（マーカー `<!-- @shared:cards -->` → `<script>` 素のスクリプト）
```js
AsobibaCards.svg(card, {w=64, faceDown=false, selected=false})  // card = {r:1..13, s:"S"|"H"|"D"|"C"} | {joker:true}. インラインSVG文字列。スート記号はパス描画（文字・絵文字は使わない）。数字は --font-num。
AsobibaCards.deck({jokers:0|1|2})            // 52(+joker) の配列
AsobibaCards.shuffle(arr, rng)               // rng は seed 付き（オンラインは room.seed から mulberry32）
AsobibaCards.rank(card)/suit/label(card)     // "A","J","Q","K" 等
AsobibaCards.backPattern(color)              // 裏面。色は各ゲームの accent
```
カード面は「白地・角丸・赤/黒2色・四隅に数字とスート・中央に大きなスート」のクラシック。裏面は各ゲームの accent 色の幾何柄。サイズは幅で指定（比率 2.5:3.5）。

## 2. ゲーム本体の共通契約
各ゲームは **純粋関数のルールエンジン**と**UI**を分ける（オンライン/CPU/交代で同じエンジンを使うため）。
```js
const Engine = {
  initialState(settings, players, rng) -> state,
  legalMoves(state, seat) -> move[],
  applyMove(state, move, seat) -> state（新オブジェクト・副作用なし。乱数が要る時は state.rngState を進める）,
  cpuMove(state, seat, rng) -> move,
  isOver(state) -> bool, result(state) -> {ranking|winner|scores, summary},
  publicView(state, seat) -> 表示用（他人の手札は枚数だけ）
};
```
- モード: 「CPUと対戦」「この端末で交代（2人〜）」「オンライン（部屋を作る／参加）」をホーム画面に同じ並びで。既存ゲームのホーム（back10/uma）と同じ構造＝名前欄→モード→開始。
- 画面: トップバー（戻るピル／タイトル＋エンブレム／メニュー・音）→ 盤面/場 → 自分の手札・操作バー（固定） → 手番バナー。結果画面は順位＋「もう一度」「ホームへ」。
- 投了・退出・配り直しは `asobibaConfirm`。無効操作は `asobibaToast`。
- ルール説明は `src/shared/rules.js` の `RULES[slug]` にも追加（ハブ側で使う。ゲーム内の「遊び方」は自己完結のため同内容を自前で持ってよい）。
- 絵文字ゼロ（`grep -P "[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}]"` で0件）。

## 8. 実機確認手順（本人が行う・本番 Firestore を使う確認はここだけ）
Phase 1 のセッションでは本番 Firebase へは一切つないでいない（Playwright では gstatic を遮断して「オンラインは使えません」経路だけ確認）。
以下は **本人が実機または PC のタブ2つ** で行う。所要 5 分。

1. `npm run dev` で dev サーバを起動（または GitHub Pages に push 後の本番URL）。`/games/othello/` を開く。
2. **タブA**: 名前を入れ「オンライン対戦」→「部屋を作る」。
   - 4桁コードのロビーが出れば OK。
   - **「オンライン対戦の準備ができていません（管理者へ: Firestore のルール設定が必要です）」** と出たら
     `docs/firestore.rules` の手順どおり Firebase コンソールでルールを足してから再試行（permission-denied）。
   - 「ネットワークに接続できません」はネット or 広告ブロッカー（gstatic.com 遮断）を疑う。
3. **タブB**（シークレットウィンドウだと別の匿名 uid になって確実）: 同じページを開き、タブAのコードを入れて「コードで参加」。
   タブAのロビーに2人目が出ることを確認。
4. タブAで「対局開始」→ 両タブが盤面になる。黒(A)→白(B) と交互にタップし、**両方の盤が同じになる**ことを確認。置けない番が来たら「パス」トーストが出る。
5. 途中でタブBを閉じる（または「メニュー→部屋を出る」）→ タブAの相手欄に CPU バッジが付き、CPU が打ち続ける。
   タブBで同じ URL（#コード付き）を開き直して参加 → 席に復帰できる。
6. 終局 → 結果シート → タブA（ホスト）の「もう一度」で色が入れ替わって再戦が始まる。タブBでも自動で新しい盤になる。
7. 別の確認: タブAのロビーで「CPUを入れる」→「対局開始」で CPU 相手に1人でオンライン対局できる。
8. 最後は「ホームへ」（または部屋を出る）で退出。Firestore コンソールの `rooms` に `othello-XXXX` が残っていれば 3 日で TTL 削除（TTL 未設定なら手で消してよい）。

問題が出たら: ブラウザの開発者ツール Console の赤字を、`asobiba/docs/03-…` のこの節の下にメモして次のセッションへ。
