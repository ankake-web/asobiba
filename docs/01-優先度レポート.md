# ゲーム全11本 UI/デザイン監査 — 優先度レポート

作成: 2026-08-15 / 対象: あそびば（ハブ＋5ゲーム）、ヘルパゴス、カタン、百万石、ドミニオン、モンスターイーター

---

## 1. 総括

土台はどれも本物。11本すべてに `:root` のデザイントークン（色・余白・角丸を変数で一元管理する仕組み）があり、演出も「タップでスキップさせない」というルールがほぼ全プロジェクトで守られている。6軸平均を見ても **polish 3.8 / visual 3.6** と高く、「作り込みが足りない」プロジェクトは1本もない。

落ちているのは別の3軸だ。**taste 2.1（11本中10本が2点）／ mobile 2.4 ／ debt 2.9**。中身は全部同じで、①UI絵文字が全部で **1,084個**、②スマホ縦持ちの実測（タップ領域44px未満が11本中10本、9〜11pxの文字が11本中11本）、③取り消せない操作に確認画面が無いのが11本中9本。つまり「絵やアニメを足す」フェーズではなく、**すでに作った良いものが、絵文字と指のサイズと確認1枚で台無しになっている**状態。

findings は全131件、うち critical 15件・high 58件。critical の中身も「凝った機能が壊れている」ではなく「レイアウトが跳ねる」「誤タップで終わる」「80MB落とす」といった素朴な事故が中心で、工数 S（小）で直るものが多い。逆に言えば、**共通ルールを1本決めて全プロジェクトに横流しするだけで、11本まとめて1段上がる**。第一印象が「素人ページ」に見える最大の単一要因は絵文字で、これは技術ではなく作業量の問題。

## 3. 各対象の詳細

### 1位｜あそびば / ハブ（2.8）

全5ゲームの入口なのに、**タイルの `<a>` の中に `<button class="rulesBtn">` が入っている**（`index.html:230`, `234`）。HTML的に不正なうえ、ボタン高さ約38px。縁を外すとゲームに即遷移する＝井上さんが一番嫌う挙動がトップ画面で起きる。さらにゲーム5本が `GAMES` 配列からJS生成のみ（`index.html:172`, `188-190`）なので、LINEやXにURLを貼ってもプレビューが空、検索にもゲーム名が1つも拾われない。OGP（SNSにURLを貼った時に出る画像と説明）もfaviconも無い。タイルの主役は118〜160pxの巨大絵文字（`index.html:107-109`, `195`, `200`, `205`）が計37個。

**最初の3手**
1. ルールボタンを `<a>` の外へ出し、タイルを「本文＝リンク／フッター行＝あそぶ＋ルール」の2段に（`index.html:230`, `234`）— S
2. ルールモーダルの `max-height:88vh` → `min(88dvh,88vh)`、`.rmPlay` を `position:sticky;bottom:0` に（`index.html:144`, `149-151`）。ついでにスクロールリセットの対象違い（`index.html:250` は `#rulesBody` だが `overflow:auto` は親の `.rulesModal`）を修正 — S
3. `head` に og:title/og:description/og:image・favicon・apple-touch-icon を追加、5タイルを静的HTMLに直書き — M

3. `placeBet`/`moveHorse` を2段階化（1タップ目＝選択、下部バーに「◯◯に2点チップを置く｜やめる｜決定」）— M

### 3位｜霧稜のクライム（2.7）

**`phase='choose'` になった瞬間に `.pairs` へ約170pxが挿入され、`flex:1;min-height:0` の `.board-wrap` が全部吸って縮む**（`index.html:222`, `115-116`）。375×812だと盤面の持ち分は元々300px前後なので、振るたびに山が半分以下に潰れて跳ねる。ここが「手作り感」の発生源。加えて `.step` が `max-height:14px` で短い山は48pxしか埋まらないのに、`placeClimber` は `track.clientHeight` 基準で位置を出すため、山2・3・4・10・11・12の6本で**駒がバーの上に浮く**（`index.html:142-147`, `574-584`）。押し引きゲームなのに「今何歩賭けているか」「次に振ったら滑落する確率」がどこにも出ていない（`index.html:714`）。

**最初の3手**
1. `.pairs` に3行ぶんの `min-height`（約170px）を固定で持たせる — S
2. `placeClimber` の基準を `track.clientHeight` からステップ群の実高さに変更 — M
3. `bank()`/`bust()` のトースト・SE・シェイクを `if(player===YOU)` の外へ出してCPU側にも出す（`index.html:743-746`, `771-775`）— S

### 4位｜BACK10（2.7）

`canPlay(card,pile)` は定義済みなのに **`playPile()` の判定（`index.html:1063`）でしか使われず、描画側は素の数字を並べるだけ**（`index.html:846`, `1032`, `1043`）。手札8枚×場札4マス＝32通りを毎ターン暗算させている。しかも出せない場札をタップすると確認なしで −50点が確定して `saveGame()` まで走る。visual 4（ホーム画面は有料アプリ級）なのに clarity 2 / polish 2 という落差がそのまま「入ったら遊べない」に出ている。`@keyframes` が confetti 1つだけ（`index.html:516`）で、その confetti に `pointer-events:none` が無く結果画面のボタンを塞ぐ（`index.html:515`, `1218`）のも痛い。

**最初の3手**

3. `.confetti` に `pointer-events:none` を1行追加（`index.html:515`）— S

## 4. 横断で共通する問題 ＝ 1回作れば11本に効く

| 病 | 出ているプロジェクト数 | 実数 |
|---|---|---|
| **UI絵文字** | **11 / 11** | 計 **1,084個**（catan 437・百万石 304・ドミニオン 125・uma 56・monster 43・ハブ 37・dice 31・ヘルパゴス 27・treasure 12・spy 7・back10 5） |
| **タップ領域44px未満** | **10 / 11** | 最小はヘルパゴスの28px、uma盤面24px、catanメニュー26px |
| **9〜11pxの極小文字** | **11 / 11** | 最小は uma の5px（GOAL/PACE表示）、ヘルパゴス8.6px、catan港ラベル実効6.2px |
| **取り消せない操作に確認なし** | **9 / 11** | 準拠はドミニオンとカタンの盤面配置のみ |
| **数字だけでメーター化されていない** | **8 / 11** | ヘルパゴスと百万石は**メーター用CSSが既にあるのに未使用** |
| **100vh依存 / dvh未使用** | 5 / 11 | catan・百万石・back10・ハブ(88vh)・ドミニオン(86vh) |
| **safe-area の欠け** | 7 / 11 | ハブは `viewport-fit=cover` 宣言だけで `env()` が0箇所 |
| **ピンチズーム禁止（user-scalable=no）** | 3 / 11 | dice-climb・treasure・ドミニオン。極小文字と併発＝逃げ道なし |
| **ヘッダーにボタン羅列** | 6 / 11 | back10は対局中7個（BGMとルールが二重） |
| **死にCSS / 未使用コード** | **11 / 11** | catan 53クラス、百万石 約110行、ヘルパゴス 約60行 |

### 提案：共通ルールを1本作って全部に流す

個別に11回やる話ではない。**「あそびば共通ルール」を1枚決めて、他プロジェクトにもコピーするのが最短**。
